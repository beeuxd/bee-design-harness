# Problem Statements

Produced and maintained by `/problem-loop`. A problem statement describes a user, their context, the struggle, and its impact — **never an embedded solution** ("users need a dashboard" is a solution wearing a problem's clothes). Every clause must map to INS-IDs in `docs/research/insights.md`. PROB-IDs are permanent; never renumber.

## Problem Inventory

| ID | Problem statement | Who (persona) | Claims → evidence | Status |
|----|-------------------|---------------|-------------------|--------|
| PROB-001 | When [context], [user] struggles to [goal] because [obstacle], which costs them [impact]. | | context: INS-…; obstacle: INS-…; impact: INS-… | Validated / Open / Unvalidated |

**Status rubric** — Validated: every clause maps to Active INS-IDs, no High-confidence insight contradicts it. Open: validation round surfaced a gap, listed below. Unvalidated: user-supplied without research backing (allowed, but labeled — it taints everything downstream that cites it).
